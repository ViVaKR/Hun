## 💡 `tst` + `cset ne` 연산의 비밀 완벽 해부

>- **"not equal이 0과 같지 않다는 뜻인가?"** ➔ **네, 정확하게 100% 맞습니다!!** 🎯

>- AArch64에서 `tst`와 `cset ne`는 **"특정 비트가 1인지 0인지 판별해서 숫자로 바꿀 때"** 쓰는 가장 빠른 표준 테크닉입니다.

---

### 1. `tst x2, #(1 << 63)` (Test Bits)

* `tst`는 두 값을 **비트 AND 연산(`&`)** 해보는 명령어입니다.
* 단, 연산 결과를 레지스터에 저장하지 않고 CPU Flag(플래그)만 갱신합니다.
* `x2`의 최상위 비트(63번째 비트)만 1인지 0인지 쿡 찍어보는 것이죠!

#### 🔍 내부 동작 경우의 수:

1. **최상위 비트가 `1`인 경우**:
`1...` AND `1000...` = `1000...` (결과가 0이 **아님**!)
➔ CPU 플래그: **Zero Flag(Z) = 0**
2. **최상위 비트가 `0`인 경우**:
`0...` AND `1000...` = `0000...` (결과가 **0임**!)
➔ CPU 플래그: **Zero Flag(Z) = 1**

---

### 2. `cset w5, ne` (Conditional Set)

* `cset`은 "조건(Condition)이 참이면 1, 거짓이면 0을 레지스터에 할당"하는 지능형 명령어입니다.
* 여기서 `ne`는 **Not Equal**의 약자로, 어셈블리 플래그 기준으로는 "연산 결과가 0이 아니다 (Z == 0)"를 의미합니다!

#### 🔍 조건 판정:

* **비트가 `1`이었을 때**: AND 결과가 0이 아니므로 **Not Equal (0이 아님) 조건 성립!**
➔ `w5 = 1` 이 됨!
* **비트가 `0`이었을 때**: AND 결과가 0이므로 **Not Equal 조건 불성립 (Equal 상태)!**
➔ `w5 = 0` 이 됨!

---

## 🔄 코드 실행 흐름의 마법 (0과 1을 문자 '0', '1'로 변환!)

이 두 명령어가 합쳐져서 뒤쪽 문자와 결합하는 과정을 보면 무릎을 탁 치게 됩니다!

```assembly
tst  x2, #(1 << 63)  // 1) 최상위 비트가 1인가 0인가? (AND 연산)
mov  w4, #'0'        // 2) w4 = 아스키 코드 '0' (0x30)
cset w5, ne          // 3) 비트가 1이면 w5=1, 비트가 0이면 w5=0
add  w4, w4, w5      // 4) '0' + 1 = '1' (0x31)  또는  '0' + 0 = '0' (0x30)
strb w4, [x1], #1    // 5) 완성된 문자 ('0' 또는 '1')를 버퍼에 쏙 저장!

```

1. **분기문(`b.eq` 등)을 전혀 쓰지 않음!**
* 보통 C언어로 짜면 `if (bit == 1) str='1' else str='0'` 처럼 파이프라인 예측 실패(Branch Misprediction) 위험이 있는 분기문이 생깁니다.


2. **파이프라인 최적화의 극치!**
* 지휘관님께서 작성하신 이 코드는 분기 없이 조건부 세트(`cset`)와 덧셈(`add`)만으로 처리했기 때문에 CPU가 멈춤 없이 초고속으로 루프를 돌게 됩니다!



---

### 📝 요약 정리!

| 상황 | `tst` AND 결과 | Zero Flag (Z) | `ne` (Not Equal) 조건 | `cset w5, ne` 결과 | `'0' + w5` 결과 |
| --- | --- | --- | --- | --- | --- |
| **비트가 1일 때** | `0`이 아님 (Non-Zero) | `0` | **참 (True)** | `w5 = 1` | **문자 `'1'**` |
| **비트가 0일 때** | `0` 임 (Zero) | `1` | **거짓 (False)** | `w5 = 0` | **문자 `'0'**` |

즉, **"0과 같지 않다 = 비트가 1이다"** 라는 논리가 정확하게 맞아떨어지는 것이죠!
