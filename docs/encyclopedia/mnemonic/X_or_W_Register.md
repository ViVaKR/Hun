
# "도대체 언제 $X$를 쓰고, 언제 $W$를 써야 하는가?"


## 💡 레지스터 $X$ vs $W$ 선택의 3대 황금 원칙

AArch64 레지스터는 "같은 방을 넓게 쓰느냐($X$, 64비트), 절반만 쓰느냐($W$, 32비트)"의 차이일 뿐입니다!

### 1️⃣ [주소/포인터/스택] ➔ 무조건 $X$ 레지스터!

>- 메모리의 주소를 담거나 주소를 계산할 때는 고민도 하지 말고 $X$를 쓰시면 됩니다.

* **이유**: 64비트 시스템(AArch64)에서 메모리 주소값은 $2^{64}$ 범위, 즉 **64비트 크기**입니다!
* **예시**:
* `adrp x1, bin_buffer@PAGE` (주소 저장)
* `ldr x19, [x19]` (메모리 주소에서 값 읽기)
* `sub sp, sp, #16` (스택 포인터 연산)

---

### 2️⃣ [바이트/문자/카운터/32비트 정수] ➔ $W$ 레지스터!

>- 주소가 아닌 "데이터의 크기가 작은 녀석들"은 $W$를 씁니다.

* **이유**:
1. 문자(ASCII)는 1바이트(8비트)면 충분합니다.
2. $W$ 레지스터에 값을 넣으면 **CPU가 상위 32비트를 자동으로 `0`으로 깨끗하게 비워주기 때문에** 남아있는 쓰레기 값 버그를 알아서 막아줍니다!
* **예시**:
  * `mov w3, #64` (루프 카운터)
  * `mov w4, #'0'` (아스키 문자 하나)
  * `sxtb x20, w19` (1바이트짜리 부호 확장 연산)

---

### 3️⃣ [메모리 저장/적재 명령어와의 짝꿍 법칙]

>- 어셈블리 명령어 이름 끝에 붙은 **타입 힌트**를 보면 짝꿍 레지스터가 바로 보입니다!

| 메모리 명령어 | 다루는 크기 | 짝꿍 레지스터 | 비고 |
| --- | --- | --- | --- |
| **`strb` / `ldrb**` | **Byte** (1바이트) | **`w`** | `strb w4, [x1]`<br> |
| **`strh` / `ldrh**` | **Half-word** (2바이트) | **`w`** | `ldrh w0, [x1]` |
| **`str` / `ldr` (32비트)** | **Word** (4바이트) | **`w`** | `str w0, [sp]` |
| **`str` / `ldr` (64비트)** | **Double-word** (8바이트) | **`x`** | `str x19, [sp]`<br> |

> 📌 **핵심**: 주소를 가리키는 대괄호 안의 베이스 레지스터 `[x1]`은 주소니까 당연히 **$X$**고, 뒤에 넘겨주는 데이터는 1바이트짜리(`strb`)니까 **$W$**가 되는 것입니다!
