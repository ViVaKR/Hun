# EOF

## EOF란?

**EOF = End Of File** (파일의 끝)이에요. 원래는 "파일을 다 읽었다"는 신호인데, 터미널 입력에서도 똑같은 개념이 적용돼요.

지금처럼 사람이 키보드로 입력하는 상황에서 EOF는 **"더 이상 줄 스트림이 안 들어온다"**는 뜻이에요. 실제로 발생하는 상황:

- macOS/Linux 터미널에서 **`Ctrl+D`**를 누르는 경우 (입력 스트림을 강제로 닫는 신호)
- 프로그램을 `./Yana < input.txt` 처럼 파일 리다이렉트로 실행했는데, 그 파일이 끝까지 다 읽힌 경우

이때 `scanf`는 **읽을 문자 자체가 아예 없어서** 변환을 시도조차 못 해요. 이 경우 반환값은 `0`이 아니라 **음수인 `-1`(매크로 이름으로는 `EOF`)**이 나와요.

## `w0 == 0`과 `w0 == -1(EOF)`의 차이

| 상황                         | scanf 반환값 | 의미                                                 |
| ---------------------------- | ------------ | ---------------------------------------------------- |
| `h` 같은 잘못된 문자 입력    | `0`          | "입력은 받았는데, 형식이 안 맞아서 하나도 못 채웠다" |
| `Ctrl+D` 또는 입력 스트림 끝 | `-1` (EOF)   | "채우고 말고 할 것도 없이, 애초에 읽을 게 없다"      |

코드에서:
```asm
cmp w0, #1
b.ne .L_bad_input   // 1이 아니면 (0이든 -1이든) 전부 "잘못된 입력"으로 취급
```

`b.ne`(not equal) 하나로 `0`과 `-1`을 **뭉뚱그려서** 같은 에러 경로로 보내고 있어요. 실용적으로는 이 정도로 충분한데, 만약 나중에 "Ctrl+D 누르면 그냥 프로그램 종료시키고 싶다" 같은 요구사항이 생기면, 그때는 이렇게 나눠줄 수 있어요:

```asm
cmp w0, #1
b.eq .L_input_ok

cmp w0, #-1
b.eq .L_terminate      // EOF면 아예 프로그램 종료

b .L_bad_input          // 0이면 (문자 잘못 입력) 에러 메시지 후 재시도
```

지금 만든 코드처럼 `Ctrl+D`도 그냥 "잘못된 선택입니다" 찍고 메뉴로 돌려보내는 정도면 실제 사용성엔 큰 문제 없어요. 다만 무한 flush 루프(`.L_bad_input_flush`)에서 EOF(`x0 == -1`)를 만나면 getchar가 계속 `-1`만 반환하니까 그 안전장치(`cmp x0, #-1 / b.eq .L_bad_input_done`)를 넣어둔 게 바로 이 상황을 막기 위한 거예요. 🍒
