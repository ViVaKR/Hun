# 퀵정렬 코드해설

[***quicksort*** source code link](./quicksort.S#1)


> 퀵정렬 에서 헷갈리는 부분은 `partition`과, `quicksort`  

## 큰 그림 먼저: `i`와 `j`가 하는 일

`partition`의 핵심은 딱 하나예요: **"피벗보다 작은 애들은 왼쪽 구역에, 큰 애들은 오른쪽 구역에 몰아넣는다."**

이걸 위해 포인터(인덱스) 두 개가 배열을 훑어요.

- **`j` (x24)**: "정찰병". `lo`부터 `hi-1`까지 배열을 한 칸씩 순회하며 각 원소를 피벗과 비교
- **`i` (x23)**: "작은 값들의 경계선". "지금까지 발견한 피벗보다 작은 값들은 인덱스 `0`부터 `i`까지에 모여있다"는 걸 항상 보장하는 경계값

`j`가 피벗보다 작은 값을 하나 발견할 때마다, `i`를 한 칸 넓히고(`i++`) 그 새 `i` 자리와 `j` 자리를 **swap**해요. 이렇게 하면 "작은 값들의 구역"이 왼쪽에서부터 차곡차곡 커져요.

## `quicksort` 본체 — 왜 이렇게 짧은지

```asm
FUNC_START_FULL quicksort, 96
	mov x19, x0   // arr
	mov x20, x1   // lo
	mov x21, x2   // hi

	// 종료 조건: 정렬할 원소가 0개 또는 1개면 이미 정렬된 거나 마찬가지
	cmp  x20, x21
	b.ge .L_qs_done   // lo >= hi 면 (구간 크기 1 이하) 더 쪼갤 게 없음 -> 그냥 리턴

	// 1단계: 이 구간[lo..hi]을 피벗 기준으로 두 편으로 가르고,
	//        피벗이 최종적으로 안착한 인덱스를 p로 받는다
	mov x0, x19
	mov x1, x20
	mov x2, x21
	bl  _partition
	mov x22, x0       // p = 피벗의 최종 위치

	// 2단계: 피벗 왼쪽 구간 [lo .. p-1] 을 "똑같은 방식으로" 다시 정렬
	//        (재귀호출 = "나보다 작은 문제를 나 자신에게 다시 맡긴다")
	mov x0, x19
	mov x1, x20
	sub x2, x22, #1
	bl  _quicksort

	// 3단계: 피벗 오른쪽 구간 [p+1 .. hi] 을 똑같이 재귀로 정렬
	mov x0, x19
	add x1, x22, #1
	mov x2, x21
	bl  _quicksort

.L_qs_done:
FUNC_EXIT_FULL 96
```

**핵심 통찰**: `partition`이 끝나면 피벗은 **더 이상 움직이지 않아도 되는 제자리**에 안착해요 (자기보다 작은 것들은 왼쪽에, 큰 것들은 오른쪽에 다 있으니까). 그래서 `quicksort`는 "피벗 빼고 왼쪽 재귀, 피벗 빼고 오른쪽 재귀"만 하면 끝이에요. **"나눠서 정복한다(divide and conquer)"**가 코드 3줄짜리 재귀호출 두 방으로 표현된 거예요.

## `partition` — Lomuto 방식 한 줄 한 줄

```asm
FUNC_START_FULL partition, 96
	mov x19, x0  // arr
	mov x20, x1  // lo
	mov x21, x2  // hi

	// ===== 1. 피벗값을 arr[hi]에서 뽑아 x22에 캐싱 =====
	// 왜 하필 arr[hi]를 피벗으로? -> 구현이 제일 간단해서.
	// (극단적으로 운 나쁜 입력에선 느려지지만, 지금 데이터엔 문제없음)
	lsl x0, x21, #3          // x0 = hi * 8  (인덱스 -> 바이트 오프셋 변환)
	ldr x22, [x19, x0]       // pivot = arr[hi]

	// ===== 2. i, j 초기화 =====
	sub x23, x20, #1  // i = lo - 1
	// "아직 작은 값을 하나도 못 찾았다" -> lo보다 한 칸 왼쪽(경계 밖)에서 시작
	// 첫 번째로 작은 값을 찾으면 i++ 해서 lo 위치부터 채우기 시작함
	mov x24, x20      // j = lo  (정찰 시작 위치)

.L_part_loop:
	// ===== 3. j가 hi 직전까지(hi는 피벗 자신이니 비교 대상에서 제외) 순회 =====
	cmp  x24, x21
	b.ge .L_part_after_loop   // j가 hi에 도달 = 순회 끝 -> 마무리 단계로

	lsl  x0, x24, #3
	ldr  x1, [x19, x0]        // 현재 정찰 중인 값 = arr[j]
	cmp  x1, x22               // arr[j] vs pivot 비교
	b.gt .L_part_continue      // arr[j] > pivot 이면 "얘는 오른쪽에 있어도 됨" -> 그냥 j++ 로 넘어감

	// ===== 4. arr[j] <= pivot 인 경우: "작은 값 구역"에 편입시킨다 =====
	add x23, x23, #1           // i++  (작은 값 구역을 한 칸 넓힘)
	lsl x2, x23, #3
	add x2, x19, x2            // &arr[i]  (새로 넓어진 경계 자리 주소)
	add x3, x19, x0            // &arr[j]  (지금 발견한 작은 값의 주소, x0 = j*8 재사용)
	ldr x4, [x2]
	ldr x5, [x3]
	str x5, [x2]                // arr[i] <- arr[j]  (작은 값을 경계 안쪽으로 이동)
	str x4, [x3]                // arr[j] <- 원래 arr[i]에 있던 값  (자리 맞바꿈)
	// 이 swap 덕분에: [lo .. i] 구간 = 지금까지 발견한 "피벗보다 작은 값들"만 존재

.L_part_continue:
	add x24, x24, #1           // j++  (다음 원소 정찰하러)
	b   .L_part_loop

.L_part_after_loop:
	// ===== 5. 순회가 끝났으면, 피벗을 "작은 구역" 바로 옆자리로 옮겨 확정 =====
	// 지금 상태: [lo..i] = 작은 값들,  [i+1..hi-1] = 큰 값들,  arr[hi] = 피벗(아직 안 옮겨짐)
	// 피벗이 있어야 할 "제자리"는 바로 i+1 번째 자리!
	// (그 왼쪽은 전부 피벗보다 작고, 그 오른쪽은 전부 피벗보다 크니까)
	add x23, x23, #1           // i를 최종적으로 한 번 더 전진 -> i+1 = 피벗이 안착할 위치
	lsl x0, x23, #3
	add x0, x19, x0             // &arr[i+1]
	lsl x1, x21, #3
	add x1, x19, x1             // &arr[hi]  (피벗이 원래 있던 자리)
	ldr x2, [x0]
	ldr x3, [x1]
	str x3, [x0]                 // arr[i+1] <- pivot
	str x2, [x1]                 // arr[hi]  <- 원래 arr[i+1]에 있던 값
	// 이제 arr[i+1] == pivot 이고, 이 위치가 정렬 후 최종 위치로 확정됨!

	mov x0, x23  // 반환값 = 피벗의 최종 인덱스 (quicksort가 이 값 기준으로 좌우를 나눠 재귀호출)
FUNC_EXIT_FULL 96
```

## 손으로 똭 한 번만 따라가 보기 (`3 1 7 9 5 2 6 4 8`, lo=0, hi=8)

피벗 = `arr[8] = 8`

| j   | arr[j] | pivot(8)과 비교 | 동작                            | i   | 배열 상태           |
| --- | ------ | --------------- | ------------------------------- | --- | ------------------- |
| 0   | 3      | ≤               | i=0, swap(0,0)                  | 0   | `3 1 7 9 5 2 6 4 8` |
| 1   | 1      | ≤               | i=1, swap(1,1)                  | 1   | `3 1 7 9 5 2 6 4 8` |
| 2   | 7      | ≤               | i=2, swap(2,2)                  | 2   | `3 1 7 9 5 2 6 4 8` |
| 3   | 9      | >               | 그냥 넘어감                     | 2   | 변화 없음           |
| 4   | 5      | ≤               | i=3, swap(3,4) → 9와 5 자리바꿈 | 3   | `3 1 7 5 9 2 6 4 8` |
| 5   | 2      | ≤               | i=4, swap(4,5) → 9와 2 자리바꿈 | 4   | `3 1 7 5 2 9 6 4 8` |
| 6   | 6      | ≤               | i=5, swap(5,6) → 9와 6 자리바꿈 | 5   | `3 1 7 5 2 6 9 4 8` |
| 7   | 4      | ≤               | i=6, swap(6,7) → 9와 4 자리바꿈 | 6   | `3 1 7 5 2 6 4 9 8` |

루프 끝. 마지막으로 `arr[i+1]=arr[7]=9`와 `arr[hi]=arr[8]=8`을 swap →

`3 1 7 5 2 6 4 8 9` — **피벗 `8`이 인덱스 7에 정확히 안착**! 왼쪽(`3 1 7 5 2 6 4`)은 전부 8보다 작고, 오른쪽(`9`)은 8보다 크죠.

이제 `quicksort`가 왼쪽 `[0..6]`과 오른쪽 `[8..8]`을 각각 재귀로 다시 이 과정을 반복하면 → 최종 `1 2 3 4 5 6 7 8 9` 완성이에요.

핵심 한 줄 요약: **`i`는 "이미 확정된 작은 값 구역의 오른쪽 끝"이고, `j`가 작은 값을 찾을 때마다 그 구역을 한 칸씩 넓혀나가는 게 Lomuto partition의 전부예요.** 🍒
