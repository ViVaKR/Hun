# `ADDS`와 `ADC` 조합

> 64비트 CPU인 ARM64에서 "어떻게 128비트(또는 그 이상)의 초대형 정수를 완벽하게 처리하는가?"를 보여주는 가장 클래식하고 아름다운 테크닉입니다!

> 이게 실제 현업이나 C# 컴파일러 밑바닥에서 어떻게 쓰이는지, 함장님 스타일로 착 붙는 **3가지 실제 사용 예시**를 가져왔습니다!

---

## 1. C# / .NET의 `Int128` 또는 `BigInteger` 덧셈 시

C# 11부터 `Int128` 및 `UInt128` 타입이 공식 추가되었습니다. C#에서 두 128비트 정수를 더할 때 JIT 컴파일러가 만드는 실제 어셈블리가 바로 이 녀석입니다!

* **C# 코드:**

```csharp
UInt128 a = ...;
UInt128 b = ...;
UInt128 c = a + b; // 128비트 덧셈!

```


* **JIT가 생성하는 ARM64 어셈블리:**
```assembly
// X0:X1 (a의 하위:상위 64비트)
// X2:X3 (b의 하위:상위 64비트)
// X4:X5 (c가 저장될 하위:상위 64비트)

adds x4, x0, x2    // 하위 64비트끼리 더함 + 올림수(Carry Flag) 발생 감지!
adc  x5, x1, x3    // 상위 64비트끼리 더할 때, 밑에서 넘어온 올림수(Carry)까지 플러스!

```


단 두 줄로 **128비트 덧셈이 완료**됩니다! 깔끔하죠? 👔

## 2. 암호학(Cryptography) & 금융 계산 (256비트/512비트 초대형 정수)

비트코인(Secp256k1)이나 RSA/AES 암호화 알고리즘, 또는 금융권의 초정밀 대수 계산에서는 128비트를 넘어 **256비트 연산**을 수행합니다. 이때 `ADC`를 사슬(Chain)처럼 줄줄이 연결합니다!

* **256비트(64비트 x 4개) 덧셈 예시:**
```assembly
// A (X0, X1, X2, X3) + B (X4, X5, X6, X7) -> 결과 (X0, X1, X2, X3)

adds x0, x0, x4    // [0~63비트]   첫 덧셈만 ADDS (캐리 갱신)
adcs x1, x1, x5    // [64~127비트]  이전 캐리 포함 + 다음을 위해 캐리 갱신(ADCS)!
adcs x2, x2, x6    // [128~191비트] 이전 캐리 포함 + 다음을 위해 캐리 갱신(ADCS)!
adc  x3, x3, x7    // [192~255비트] 마지막 상위 비트 연산!

```


> **💡 수부타이 제독의 포인트:**
> 중간 과정에서는 `ADC` 뒤에 `S`를 붙인 **`ADCS`**를 써서 **"올림수를 받기도 하고, 내 상위 비트로 넘겨줄 올림수도 다시 계산해라!"** 라고 명령합니다. 도미노처럼 올림수가 줄줄이 넘어가는 예술적인 구조입니다!

## 3. 고성능 타임스탬프 (64비트 나노초 넘침 방지)

시스템 타임스탬프를 **나노초(ns)** 단위로 오래 측정하다 보면, 64비트 정수(약 584년 분량)로도 모자라거나 정밀한 연산을 위해 128비트 타이머 카운터를 쓸 때가 있습니다.

```assembly
// X0: 현재 시각 하위 나노초, X1: 현재 시각 상위 나노초
// X2: 경과한 나노초

adds x0, x0, x2    // 시간이 지나서 하위 64비트 카운터가 오버플로우되면?
adc  x1, x1, xzr   // 상위 64비트에 알아서 +1 (Carry)이 쏙 더해짐! (XZR = 0번 레지스터)

```

> **XZR(Zero Register)**을 활용해서 `adc x1, x1, xzr` 을 해주면 **"하위에서 올림수가 발생했을 때만 상위에 +1을 해라"** 라는 엄청나게 멋진 구문이 완성됩니다!
